# TK-021 — Merge pela interface do GitHub já com o título do PR (#n)

> **Por que isso importa:** este registro junta, num lugar só, a prova de que o item seguiu o processo
> (branch, testes, segurança, documentação). O `scripts/dod_check.py <ID>` confere cada seção contra o
> git e o GitHub; a Sprint Review usa o mesmo arquivo.

- **Sprint:** 14 · **Issue:** #229 · **Branch:** `chore/TK-021-merge-com-titulo-do-pr` · **PR:** #<n>

## Entrega
Ação da retrospectiva da Sprint 13. Depois do DEBT-008, os merges feitos pela interface do GitHub (#223, #224, #226, #228) saíram com "Merge pull request #n from ...". O padrão do repositório continuava o antigo (`merge_commit_title=MERGE_MESSAGE`).

- **Configuração versionada** em `.github/repositorio.json`: `merge_commit_title=PR_TITLE` e `merge_commit_message=BLANK`. A escolha do corpo vazio foi do usuário: o commit de merge fica igual ao do executor, e a descrição fica no PR.
- **Aplicada no GitHub em 2026-11-11**, com a confirmação do usuário: `gh api -X PATCH repos/{owner}/{repo} --input .github/repositorio.json`.
- **`scripts/dod_check.py`:** `configuracao_esperada` e `divergencias_do_merge`. Todo `dod_check` passa a conferir a configuração ao vivo e falha se ela divergir ou se a API omitir os campos.

| Critério de aceite | Prova |
|---|---|
| O merge pela interface sai com o título do PR seguido de (#n), sem editar à mão | Configuração aplicada (a API devolve `PR_TITLE` e `BLANK`). O GitHub monta o título como "<título do PR> (#n)". O próximo merge pela interface, feito pelo usuário, fica como prova no fechamento. |
| A configuração está versionada, e um teste ou o `dod_check` confere | `.github/repositorio.json`; `TestConfiguracaoDoMerge` (5 testes); o `dod_check` acusou a configuração antiga antes da mudança e passa depois |
| O working-agreement e o sprint-executor dizem que o merge pela interface já sai no padrão | `docs/roadmap/working-agreement.md` (seção de commits) e passo 7 do `.claude/skills/sprint-executor/SKILL.md` |

## Testes

  - Cobrem o arquivo versionado, o repositório no padrão e o padrão antigo do GitHub apontado.
