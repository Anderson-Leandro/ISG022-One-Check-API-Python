# TK-017 — Proteger as branches main e dev: merge só por PR e com CI verde

> **Por que isso importa:** este registro junta, num lugar só, a prova de que o item seguiu o processo
> (branch, testes, segurança, documentação). O `scripts/dod_check.py <ID>` confere cada seção contra o
> git e o GitHub; a Sprint Review usa o mesmo arquivo.

- **Sprint:** 12 · **Issue:** #98 · **Branch:** `chore/TK-017-protecao-branches` · **PR:** #123

## Entrega
- Ruleset **"Proteção da main e da dev (TK-017)"** (id 26780877) ativo no GitHub, versionado em `.github/rulesets/protecao-branches.json`.
- **Escopo ampliado para a `dev`:** os critérios citavam só a `main`, mas todo o código é integrado na `dev`. Ampliação aprovada pelo usuário em 2026-11-07, na execução.
- **Critérios de aceite → prova:**
  - **Merge só por PR, sem exigir aprovação:** regra `pull_request` com `required_approving_review_count: 0`. O autor pode mesclar o próprio PR, e o PR deste item é a prova.
  - **Checks do `tests.yml` obrigatórios:** regra `required_status_checks` com `test` e `dependencias`, presos ao app GitHub Actions (`integration_id` 15368), para que outro app não consiga se passar pelo check.
  - **Push direto recusado:** testado uma vez (abaixo).
- **Também na regra:** sem force-push (`non_fast_forward`), sem apagar a branch (`deletion`) e sem exceções (`bypass_actors: []`), nem para o dono do repositório.
- **Regras efetivas conferidas** com `gh api repos/.../rules/branches/{main,dev}`: `deletion`, `non_fast_forward`, `pull_request` e `required_status_checks` nas duas.

## Testes
- **Cenário negado, numa branch descartável** (`teste-protecao-tk017`), incluída temporariamente na mesma regra. Nem a `main` nem a `dev` receberam tentativa de push. Um commit vazio enviado direto foi recusado:
  ```
  remote: error: GH013: Repository rule violations found for refs/heads/teste-protecao-tk017.
  remote: - Changes must be made through a pull request.
  remote: - 2 of 2 required status checks are expected.
   ! [remote rejected] HEAD -> teste-protecao-tk017 (push declined due to repository rule violations)
  ```
  Depois do teste, a branch saiu da regra e foi apagada (`git ls-remote` sem resultado).
- Item sem código: a suíte do pytest não muda. O CI do PR roda normalmente e é ele que libera o merge sob a nova regra.

## Segurança
- `/security-audit diff dev` em 2026-11-07: os scanners aplicáveis com status `ok` (bandit pulado: nenhum `.py` no diff). **Nenhum achado novo.** Os 4 resultados (arquivo de segredos local fora do índice, valores fictícios em teste, `HEALTHCHECK` no Dockerfile) são anteriores, ficam fora do diff e já tinham sido avaliados no relatório de 2026-11-07.
